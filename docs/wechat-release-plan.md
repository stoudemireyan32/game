# 微信小游戏发布准备（2026-11-08）

当前目标是**微信小游戏**，不是把HTML塞入普通小程序web-view。H5继续供快速试玩；后续将核心玩法迁入支持微信小游戏的2D工程。

## 现在已完成

- 三消规则、GPU解锁/数据/模型成长是独立纯JS模块：`engine.js`、`economy.js`；可继续复用，已有规则回归。
- `npm run prepare:wechat`可重复导出`dist/wechat-preparation/`：纯规则、8种品牌PNG、GPU/数据概念图、6段本地MP3、规格/模型配置与许可。此次25文件、447662字节。
- 导出包明确标记`preparation-only-not-runnable`，**不是可运行/可上传工程**；没有伪造AppID、微信入口或声称已经适配。
- 说明内容集中在`guide.js`，网页内与独立`guide.html`共享；微信版本需用场景/UI重画手册，不依赖HTML弹窗。

## 技术路线与次序

建议使用 **Cocos Creator 2D** 做微信版本，保留现有规则和经济参数。用同一引擎同时导出网页与微信，减少长期维护两套UI；这一步不是继续套浏览器CSS，也不需要Three.js。

| 阶段 | 我来做 | 账号持有人配合 | 完成标准 |
|---|---|---|---|
| 1. 账号准备 | 整理名称、图标、简介、玩法说明、素材来源与数据处理说明 | 在公众平台注册/确认小游戏账号、主体，取得AppID，添加开发者 | 能用本人账号在开发者工具导入正确小游戏AppID |
| 2. 工程适配 | Cocos 2D棋盘/资源卡/动效/说明页，复用三消与成长；音频、触摸、安全区、后台切换和本地存档适配 | 提供非密钥的AppID及开发者权限；需要扫码的操作本人完成 | 微信开发者工具可运行，规则回归通过 |
| 3. 真机体验版 | 构建、包体/性能检查、修复iOS/安卓/低端机问题，准备体验流程 | 本人微信扫码，添加体验成员，在真实手机试听和试玩 | 三消→获A100/H100→训练→退出重进可完成，音乐/人声/安全区正常 |
| 4. 审核与发布 | 整理提交物、隐私与素材说明，处理技术审核问题 | 核对主体/类目/资质；在自己的后台提交审核，审核通过后发布 | 通过平台审核并由持有人发布 |

当前H5可直接复用：规则、解锁数值、品牌主题、音频文件、文字内容。需要重写/适配：DOM/CSS绘制和CSS动画、PointerEvent命中、Web Audio混音、localStorage、dialog和页面生命周期。原生Canvas只提供渲染上下文，不会自动运行现有HTML布局。

存档使用平台适配层：微信侧用`wx.getStorageSync / wx.setStorageSync`或引擎支持的持久化。音频用引擎AudioSource/平台音频接口；触摸用引擎输入，前后台对接生命周期。网页与微信存档默认独立，不能承诺自动迁移；如果要跨端同步需另做身份与云存档方案。

## 首发范围建议

先保持无登录、无支付、无广告、无排行榜的单机自动存档版。已有游戏逻辑不需要真实大模型调用、GPU采购或MaaS后端。云存档/好友排行/广告等后加，届时再配置对应权限、合法域名、隐私与服务端校验。不能把开发工具关闭域名校验当作正式环境方案。

首发需实际核对：名称/头像/简介/截图；音乐与品牌图标的发行使用范围（开源图形许可不自动授予商标授权）；真实的数据处理情况；账号主体和游戏类目要求的备案、出版/版号、适龄、实名/防沉迷等适用材料。**本次未能读取当前完整审核条款，不能断言某种主体可免某项资质，也不承诺审核时限。以账号后台和现行审核要求核对。**

## 上传与权限

初期通过微信开发者工具手动预览、上传体验版即可。后续需要自动上传时，可以使用微信官方`miniprogram-ci`；本次仅查询其公开包元数据，未安装、未配置上传。其开发权限、上传私钥及IP白名单应在受控环境配置，不提交代码仓库、不贴聊天。自动上传也不等于审核通过或自动公开发布。

我能处理云端代码、资源、构建和自动化测试；不能代替持有人完成主体认证、本人微信扫码或在未登录授权的电脑上操作后台。
